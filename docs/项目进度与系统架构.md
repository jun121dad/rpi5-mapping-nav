## 一、项目目标与当前状态

### 目标

在一台自制移动机器人上实现：

1. **边建图**：用深度相机实时构建 2D 占据栅格地图
2. **边导航**：在地图上点击目标点，机器人自主规划并到达
3. **边检测**：NPU 实时识别物体，把类别和位置写进地图，形成**语义地图**
4. **语义搜索**：说"找到杯子"，有则导航过去，无则自动探索

| 检测 | ✅ 可用 | YOLOv6n @ NPU，30 fps |

## 五、核心数据流

### 5.1 建图链路（35 ms 一圈）

```
深度图 640×480×30
   │ ① 按内参反投影成 3D 点
   ▼
光学系点云
   │ ② TF 转到 base_link（补偿相机俯仰/横滚）
   ▼
base_link 点云
   │ ③ 高度带筛选
   ├─ 障碍带 0.10–0.80 m ──► 标记障碍
   └─ 地面带 −0.04–0.10 m ──► 标记空闲（填房间中间）
   │ ④ 按角度分箱（640 束，±39.5°），每束取最小值
   ▼
/scan (29 Hz)
   │ ⑤ slam 扫描匹配 + 位姿图优化
   ▼
/map (1–2 Hz) + map→odom
```

### 5.2 检测链路（33 ms 一帧）

```
彩色 640×480×15
   │ ① ROS → v4l2 虚拟摄像头
   ▼
/dev/video10 (YUYV)
   │ ② 容器：YUYV→RGB，缩放到 640×640
   ▼
NPU 推理 YOLOv6n（13 TOPS）
   │ ③ NMS（score 0.3 / IoU 0.45）
   ▼
DETJSON {"frame":n,"det":[{label,conf,x,y,w,h}]}
   │ ④ 主机解析，归一化 → 像素
   ▼
/detections_2d (30 fps)
```

### 5.3 语义投影链路

```
检测框中心 (u,v)
   │ ① 查深度图中值（窗口 9×9，无效则偏移重试）
   ▼
深度 Z
   │ ② 内参反投影：X=(u−cx)Z/fx, Y=(v−cy)Z/fy
   ▼
光学系 3D
   │ ③ TF → map
   ▼
map 坐标 (x,y,z)
   │ ④ 过滤：z ∈ [−0.05, 1.20] m
   │ ⑤ 聚类：同类且 0.6 m 内 → 累加平均
   ▼
/semantic_map (MarkerArray)
/semantic_map.json
```

### 5.4 搜索决策链路

```
输入 "找到红色杯子"
   │ ① 别名表匹配 → 目标类别 cup（颜色仅记录）
   ▼
SEARCHING
   │ ② 查语义地图：cup 且观测≥5 且置信≥0.45？
   ├─ 有 ──► NAVIGATING ──► NavigateToPose(x,y) ──► DONE
   └─ 8 秒内无 ──► EXPLORING
                    │ ③ 调控制台 auto 模式，边走边找
                    ├─ 发现 ──► 切手动停车 → NAVIGATING
                    └─ 180 秒超时 ──► FAILED
```

## 六、关键技术原理

### 6.1 深度图转 2D 激光（自研，替代 depthimage_to_laserscan）

**为什么自己写**：标准包把扫描发在光学系，而 LaserScan 语义要求点落在该帧的 x-y 平面；光学系 x-y 是**竖直**的，导致点被贴到墙上（地图成星芒）。

**做法**：

1. 用内参把像素反投影成光学系 3D 点
2. 用 TF 转到 `base_link`（这一步自然补偿相机俯仰）
3. **双高度带筛选**：
   - 障碍带 `0.10–0.80 m` → 墙、家具
   - 地面带 `−0.04–0.10 m` → 射线穿过空地，把中间区域标成空闲
4. 按角度分箱，每束取最小距离（障碍优先于地面）

**效果**：地图从 8×51（星芒）变成 77×77（连贯扇面）。

### 6.2 里程计融合

**问题**：四轮滑移转向，轮式 yaw 不可信（实测原地转 90°，轮子只报 18°）。

**方案**：互补滤波

```
wz = 1.0 × 陀螺 + 0.0 × 轮式      （航向纯陀螺）
位置 = ∫ vx × (cos θ, sin θ) dt   （位置用轮速）
```

**标定结果**：

| 参数 | 值 | 方法 |
|---|---|---|
| 陀螺比例 | `0.0002663` rad/s/count（±500 °/s） | 手推 90° 实测，误差 0.2° |
| 轮速比例 | `1.097` | 墙当尺子，直行 0.64 m 实测 |
| 零偏 | 自动标定 + 静止/直行时跟踪 | 静止 60 秒漂移 0.075° |
| 协方差 | x,y=0.02；yaw=0.001 | 告诉 slam"位置可纠、方向可信" |

### 6.3 抗抖动积分

| 情况 | 处理 |
|---|---|
| dt 正常（40–70 ms） | 钉回标称 50 ms，消除抖动 |
| dt 偏小 | 下限 30 ms |
| dt 过大（丢帧） | 用实际间隔按速度补偿，不再丢弃位移，并记告警 |

### 6.4 语义投影与聚类

- 检测框中心 → 深度中值 → 反投影 → TF → map
- 同类且 0.6 m 内合并，位置取**观测加权平均**（抑制抖动）
- 只发布观测次数 ≥3 的物体（过滤误检）

### 6.5 时间戳处理（关键坑）

相机时间戳是**设备内部时钟**（与系统时间差几十年）。slam 拿它查 TF 会得到错误位姿。解决：扫描统一用**处理时刻的系统时间**，因为我们本来就用最新 TF 转换。

## 十、资源占用与算力评估

### 10.1 三合一满载（实测）

| 组件 | CPU | 内存 |
|---|---|---|
| 相机 | 0.16 核 | 230 MB |
| depth_scan_fixed | 0.10 核 | 60 MB |
| ros_v4l2_bridge | 0.25 核 | 80 MB |
| **容器（视频转换+推理）** | **0.58 核** | 350 MB |
| slam_toolbox | 0.10 核 | 100 MB |
| Nav2（11 节点） | 0.50 核 | 800 MB |
| detection_bridge + semantic | 0.28 核 | 100 MB |
| 控制台 | 0.25 核 | 150 MB |
| **合计** | **≈2.5 核 / 4 核（62%）** | **≈1.9 GB / 4 GB** |

### 10.2 瓶颈判断

- **不是 NPU**：YOLOv6n @640×640 跑 30 fps，NPU 负载约 30–40%
- **是 CPU 的视频流水线**：色彩转换 + 缩放占 0.58 核
- **峰值会掉帧**：容器启动时 `scan` 从 27 Hz 掉到 9 Hz

### 10.3 优化空间

| 优化 | 省下 CPU |
|---|---|
| 容器直读 `/dev/video4`，去掉 v4l2 桥接 | 0.35 核（14%） |
| 检测降到 10–15 fps | 0.25 核（10%） |
| 关 GNOME 桌面 | 0.10 核（4%） |
| 检测输入降到 424×240 | 0.15 核（6%） |

**做完前三项，可降到约 1.9 核（47%）**，余量翻倍。
