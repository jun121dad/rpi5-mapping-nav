# 三合一使用手册

> 边建图 · 边导航 · 边检测
> 树莓派 5（4 GB）+ AI HAT+（Hailo-8L 13 TOPS）+ RealSense D455F + WHEELTEC 四驱底盘
> 版本：2026-11-12

---

## 一、这套系统能做什么

| 能力 | 说明 |
|---|---|
| **建图** | 用深度相机实时构建 2D 占据栅格地图 |
| **导航** | 在地图上点一个点，车自己规划路线过去 |
| **检测** | NPU 实时识别 80 类物体（人、杯、瓶、椅、桌、笔记本…） |
| **语义地图** | 把检测到的物体连同**坐标**记进地图，存成 JSON |
| **目标搜索** | 说「找到杯子」，有就导航过去，没有就自动探索 |

**核心特点**：三件事**同时进行**，一次启动，不需要切换模式。

## 二、开机三步

### 第 1 步：上电

```
1. 打开底盘电源（电池开关）
2. 等待树莓派启动（约 40 秒，绿灯停止闪烁）
3. 确认风扇转动、屏幕/HMI 正常
```

### 第 2 步：启动控制台

SSH 登录（IP 见路由器，或问管理员）：

```bash
ssh pi@192.168.4.193
bash /home/pi/start_console.sh
```

看到 `console on http://0.0.0.0:8080/` 即成功。

### 第 3 步：打开网页

浏览器访问：

```
http://192.168.4.193:8080/
```

> **IP 会随网络变化**（例如从 192.168.110.193 变成 192.168.4.193）。连不上时先用 `ping` 确认树莓派在哪个地址。

### 第 4 步：点「▶ 开始建图」

等 **约 150 秒**（各服务启动时间不同）：

| 服务 | 启动耗时 |
|---|---|
| 相机 | 9 秒 |
| 扫描 + 桥接 + TF | 4 秒 |
| SLAM | 6 秒 |
| Nav2（11 个节点） | 40 秒 |
| 检测容器 | 40–60 秒 |

期间顶栏 `DETECT` 显示 `OFF` 是正常的。

### 3.1 顶栏字段

| 字段 | 正常值 | 含义 |
|---|---|---|
| `STATE` | `MAPPING`（绿） | 系统状态；`IDLE`=未启动，`ERROR`=异常 |
| `MODE` | `MANUAL · NAV2` | 手动模式 + Nav2 已激活 |
| `MAP` | `52×71` 之类 | 地图格数（0.05 m/格） |
| `DETECT` | `30fps·6`（绿） | 检测帧率 · 语义物体数 |
| `BATT` | `12.4V` | 电池电压，低于 11.5 V 变红 |
| `TEMP` | `60°C` | SoC 温度，>78 °C 变红 |
| `VEL` | `0.00/0.00` | 当前线速度/角速度 |
| `ODO` | `0.00m` | 累计里程 |
| `CLOCK` | `14:11:01` | 树莓派时间 |

### 3.2 地图区

| 颜色 | 含义 |

| **白色** | 空闲可通行 |

| **红色小点** | 激光点 |

| 白 | tv（电视） | 黄 | mouse（鼠标） |

### 3.4 右栏按钮

| 按钮 | 作用 | 注意 |

## 四、建图操作

### 4.1 开始建图

1. 点「▶ 开始建图」
2. 等 `STATE` 变成 `MAPPING`、`DETECT` 变成 `30fps·N`
3. 用键盘方向键或网页方向键**慢慢开**

### 4.2 如何开得好

| 要点 | 说明 |
|---|---|
| **慢** | 0.10–0.15 m/s，速度上限滑条别拉太高 |
| **转圈** | 每走 1–2 m 原地转一圈，让相机扫到四周 |
| **回头** | 走一段后原路返回，帮助 SLAM 回环 |
| **避免空旷** | 尽量贴着墙/家具走，有特征才好定位 |
| **避免纯旋转** | 原地长时间转容易漂 |

### 4.3 键盘控制

| 键 | 作用 |
|---|---|
| `↑` / `↓` | 前进 / 后退 |
| `←` / `→` | 左转 / 右转 |
| `空格` | 急停 |

> 松开按键约 0.5 秒后自动停车（安全超时）。

### 4.4 速度上限

右栏滑条控制最大速度（0.04–0.20 m/s）。**建图建议 0.10–0.12**。

### 4.5 存图

- **自动**：停止时会存到 `/home/pi/maps/autostop_<时间>.pgm`
- **手动**：点「💾 立即存图」→ `/home/pi/maps/autosave.pgm`
- **导出到电脑**：

```powershell
scp pi@192.168.4.193:/home/pi/maps/autostop_*.pgm .
scp pi@192.168.4.193:/home/pi/maps/autostop_*.yaml .
```

## 五、导航操作

### 5.1 点击导航（最常用）

1. 在地图上点一个**白色区域**（灰色未知区不能规划）
2. 出现青色十字，车自动规划路径
3. 到达后自动停止

**注意**：

- 目标点离障碍太近会失败（膨胀半径 0.32 m）
- 未知区域（灰色）不能作为目标
- 到点误差约 **20–25 cm**

### 5.2 方向键遥控

用方向键把车开到目标附近，适合精细调整。

### 5.3 自动探索

点「🤖 自动探索」→ 车自己慢慢游走，边扫边建图。

**⚠️ 会动车，点之前确认周围安全。**

### 5.4 取消

- 点「✖ 取消目标」→ 取消当前导航
- 点「STOP」→ 立即停车

## 六、检测与语义地图

### 6.1 检测自动运行

启动后检测就在跑，不需要额外操作。顶栏 `DETECT` 显示 `30fps·N`。

### 6.2 看识别结果

**方式 1：看地图上的彩色方块**

每个方块 = 一个识别到的物体，颜色对应类别。

**方式 2：查状态**

```bash
curl -s localhost:8080/state | python3 -m json.tool | grep -A2 '"cls"'
```

**方式 3：看 JSON 文件**

```bash
cat /home/pi/maps/semantic_map.json
```

格式：

```json
{
  "frame": "map",
  "objects": [
    {"cls": "cup", "x": 1.52, "y": -0.05, "z": 0.130, "conf": 0.73, "observations": 3831}
  ]
}
```

| 字段 | 含义 |
|---|---|
| `cls` | 类别（COCO 英文名） |
| `x` / `y` | 地图坐标（米） |
| `z` | 离地高度（米），可用来区分桌面/地面物体 |
| `conf` | 置信度 |
| `observations` | 被观测次数（越大越可信） |

### 6.3 让检测更准

| 问题 | 调整 |
|---|---|
| 误检多 | 提高 `min_conf`（0.45 → 0.55） |
| 漏检 | 降低 `min_conf`（0.45 → 0.35） |
| 同一物体出现在多个位置 | 加大 `cluster_radius`（0.6 → 0.9） |
| 小物体被合并 | 减小 `cluster_radius`（0.6 → 0.3） |

## 七、目标搜索

### 7.1 怎么用

在搜索框输入中文目标，按回车或点 🔍：

| 输入 | 识别为 |
|---|---|
| 找到杯子 / 红色杯子 | `cup` |
| 找到瓶子 | `bottle` |
| 找到椅子 | `chair` |
| 找到人 | `person` |
| 找到遥控器 | `remote` |

> **颜色不生效**：COCO 模型不输出颜色，「红色杯子」只会按 `cup` 搜索。

### 7.2 搜索流程

```
输入「找到杯子」
      ↓
[SEARCHING]  查语义地图（8 秒）
      ├─ 有 cup → [NAVIGATING] 导航过去
      │              ↓ 到达
      │          [VERIFYING] 看相机里有没有 cup（5 秒）
      │              ├─ 有 → [DONE]「确认看到 cup，任务完成」
      │              └─ 无 → 「到达但没看到 cup，继续搜索」
      │
      └─ 没有 → [EXPLORING] 前沿探索
                    ├─ 相机中途看到 → 导航过去
                    ├─ 到一个点没看到 → 标记已访问，找下一个前沿
                    └─ 300 秒 → [FAILED]
```

### 7.3 状态条含义

```
[SEARCHING]  目标:cup 已访:0   开始搜索 cup
[EXPLORING]  目标:cup 已访:3   前沿探索 → (2.31, -1.05)
[NAVIGATING] 目标:cup 已访:3   语义地图发现 cup → (1.52, -0.05)
[VERIFYING]  目标:cup 已访:3   已到达，验证目标...
[DONE]       目标:cup 已访:3   确认看到 cup，任务完成
[FAILED]     目标:cup 已访:5   探索超时，未找到 cup
```

### 7.4 停止搜索

输入 `停止` 或点「STOP」。

## 十、故障排查

### 10.1 网页打不开

| 检查 | 做法 |
|---|---|
| IP 变了 | `ping` 找树莓派新地址（看路由器后台） |
| 控制台没起 | `bash /home/pi/start_console.sh` |
| 缓存 | `Ctrl + Shift + R` |
| VPN 干扰 | 关掉 Radmin VPN 等 |

### 10.2 `DETECT` 显示 OFF

| 原因 | 处理 |
|---|---|
| 容器还在启动 | 等 60 秒 |
| Docker 卡死 | `sudo systemctl restart docker` |
| NPU 被占 | `sudo fuser -v /dev/hailo0`，然后 `docker rm -f $(docker ps -aq)` |
| 容器反复失败 | 看 `/home/pi/mapping_logs/console/*/detect.log` |

> 已加保护：容器失败最多重试 6 次（3/6/12/24/30 秒退避），**不会再拖垮 Docker**。

### 10.3 地图出现"幽灵墙"（车旁边一圈黑）

| 原因 | 处理 |
|---|---|
| 地面射线被当成障碍 | 已修：`ground_clear=False` |
| 近处杂物/车体 | 已修：`min_height=0.20`、`range_min=0.45` |
| 仍出现 | 检查 `z` 值是否异常（用 `ghost_diag.py`） |

### 10.4 地图不长大 / 只在车前方

**这是 D455F 视场只有 79° 的固有限制**，不是故障。

对策：多转圈、多回头；长期方案是加 360° 雷达。

### 10.5 Nav2 不导航

| 检查 | 做法 |
|---|---|
| Nav2 是否活着 | 点「♻ 恢复导航」 |
| 目标是否在灰色区 | 灰色不能规划，点白色区 |
| 代价地图 | 看 `ros2 topic echo /local_costmap/costmap --once` |

### 10.6 车不走 / 乱走

| 原因 | 处理 |
|---|---|
| 串口没连 | `ls /dev/ttyACM0` |
| 速度超时 | 正常保护，0.5 秒无命令自动停 |
| 双栈冲突 | `bash /home/pi/clean_all.sh` 后重新开始 |

### 10.7 树莓派突然掉线 / 重启

**大概率是供电问题**（已确认 5V 只有 4.81 V，低于规格下限 4.85 V）。

| 措施 | 说明 |
|---|---|
| 调高压降模块输出 | 到 5.15 V（满载 ≥5.0 V） |
| 加 1000 µF 电容 | 吸收 AI HAT 电流尖峰 |
| 换短粗线 | 20 AWG，<30 cm |
| 测电压 | `vcgencmd pmic_read_adc \| grep EXT5V` |

**空载 <4.9 V 或满载 <4.75 V 就有风险。**

## 十一、已知限制

| 限制 | 说明 | 对策 |
|---|---|---|
| **视场 79°** | 建图只能看到前方，需多转圈 | 加 360° 雷达（约 350 元） |
| **量程 3.5 m** | 远处墙看不见 | 可调到 6 m |
| **深度噪声** | 边缘有飞点 | 已有滤波，可进一步加强 |
| 只认 COCO 80 类 | 不支持颜色/材质 | 需要额外训练 |
| 位置漂移 | 轮式滑移 | IMU 已融合，长距离仍会漂 |
| 到点误差 | 约 23 cm | 调 `xy_goal_tolerance` |
| 4 GB 内存 | 约用 1.9 GB | 不能加 rtabmap |
| **供电偏弱** | 满载 4.72 V | 见 10.7 |

## 附录 A：2026-11-12 修复的两个隐蔽 Bug

这两个问题曾导致"整机随机卡死"和"检测跑不起来"，排查过程记录在此，避免重复踩坑。

### A.1 `ros_v4l2_bridge` 内存泄漏（整机卡死的元凶）

**现象**：系统跑几分钟后变慢，最终 SSH 都连不上，负载飙升。

**根因**：桥接把彩色帧推进 GStreamer `appsrc`，但队列**没有上限**：

```python
'appsrc name=src is-live=1 format=time do-timestamp=1 block=0 '   # ← 无 max-bytes
```

当 `/dev/video10` 没有读者（检测容器没起或卡住），`v4l2sink` 阻塞，
帧在 `appsrc` 里无限堆积：614 KB × 15 fps ≈ **9 MB/秒**，3 分钟就吃掉 1.6 GB。

**实测**：

```
15:49:39  v4l2 桥接 1150 MB
15:50:10  v4l2 桥接 1556 MB   （每 30 秒涨 400 MB）
15:50:41  v4l2 桥接 1957 MB   可用内存只剩 587 MB
```

**修复**：

```python
'appsrc name=src is-live=1 format=time do-timestamp=1 block=0 '
'max-bytes=3000000 max-buffers=8 leaky-type=downstream '
```

`leaky-type=downstream` = 队列满时丢最旧的帧，内存恒定。

**修复后**：v4l2 桥接稳定在 **84 MB**，可用内存恒定 2.3 GB。

### A.2 时间戳倒流（检测 0 帧的元凶）

**现象**：检测容器启动后一直 `0 fps`，300 秒后报 `GStreamer Error: Internal data stream error`。

**根因**：桥接用相机的 `header.stamp` 当 GStreamer PTS：

```python
buf.pts = Gst.util_uint64_scale_int(msg.header.stamp.sec, Gst.SECOND, 1) + msg.header.stamp.nanosec
```

而 D455F 的时间戳来自**硬件时钟，会周期性重置**（相机日志明确警告
`frame's time domain is HARDWARE_CLOCK. Timestamps may reset periodically.`）。
时间戳一旦倒流，v4l2 设备就拒绝缓冲，**任何读者（包括容器）都取不到帧**。

**验证**：主机自己读 5 帧，12 秒超时读不到。

**修复**：改用单调时钟

```python
now_ns = time.monotonic_ns()
if self.last_pts is not None and now_ns <= self.last_pts:
    now_ns = self.last_pts + 1
self.last_pts = now_ns
buf.pts = now_ns
```

**修复后**：读 5 帧 **0.26 秒**，检测恢复 **30.3 fps**。

### A.3 Nav2 因代价地图越界退出

**现象**：`nav_active` 变 False，Nav2 进程全部消失。

**根因**：全局代价地图默认等于静态地图尺寸（刚开始只有 1.9×2.1 m），
车稍微走到边界外 1 cm 就触发：

```
Sensor origin at (-0.01, 0.01) is out of map bounds (0.00, -1.21) to (1.88, 0.87)
Robot is out of bounds of the costmap
```

**修复**：全局代价地图改为跟随车的滚动窗口

```yaml
global_costmap:
  global_costmap:
    ros__parameters:
      rolling_window: true
      width: 20
      height: 20
      update_frequency: 2.0
```

### A.4 排查手法（可复用）

```bash
# 1. 看谁在吃内存
for p in $(ls /proc | grep -E '^[0-9]+$'); do
  rss=$(awk '/VmRSS/{print $2}' /proc/$p/status 2>/dev/null)
  name=$(cat /proc/$p/comm 2>/dev/null)
  [ -n "$rss" ] && echo "$rss $name"
done | sort -rn | head -10

# 2. 定期采样（/home/pi/mem_watch.sh）
tail -20 /home/pi/mem_log.csv

# 3. 检查视频设备是否真能读
timeout 12 v4l2-ctl -d /dev/video10 --stream-mmap --stream-count=5
#   超过 1 秒还没返回 = 时间戳或缓冲有问题
```
